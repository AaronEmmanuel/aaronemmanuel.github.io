Engineering progression

The failures shaped
the final architecture.

01

Establish the baseline

Make contact do the work.

A seven-joint Franka Panda operates under gravity, collision geometry, joint limits and gripper forces. A scripted pick-and-place baseline supplied 60 expert episodes. Objects are carried by finger contact, with no attachment toggle or pose write to rescue a grasp.

02

Learn from the failed approach

Direct imitation did not become dependable.

Initial action cloning completed 0/18 tasks; corrective cloning also completed 0/18. Recovery-augmented cloning reached 6/18. Those failures remain part of the project. A different PyTorch model learns a 6-by-7 robot Jacobian from 60,000 synthetic kinematics samples, with 12,000 validation samples. Conventional feedback uses its predictions; task phases and gripper sequencing remain engineered.

03

Ground language in actual pixels

A request needs a checked visual target.

Pinned Qwen3-VL receives the operator’s request and an actual numbered RGB camera image. It proposes a target; schema, colour, geometry and image-space rank checks authorize that proposal. Calibrated RGB-D estimates the target pose. Generic, absent or duplicate-colour requests require clarification. The model is not supplied a simulator object-truth inventory.

04

Measure the bottleneck

Bring inference and control onto Ubuntu.

The first CPU model deployments exposed instruction-set and memory limits. A pinned llama.cpp runtime made the ARM64 deployment viable. Paired fresh-image experiments reduced median inference from 34.26 to 4.80 seconds. Separating display previews from depth sensing reduced a paired complete task from 131.29 to 74.06 seconds with identical recorded trajectory and pixels. These historical stepped experiments are separate from the final continuous protocol.

05

Supervise continuous execution

Keep checking while the model or operator waits.

A separate ROS 2 server advances physics and publishes stamped camera and robot feedback. The controller supervises freshness, communication and active-command leases, held contact and progress. One missed grasp permits a bounded retry. Target movement or lost feedback halts execution. Stop is acknowledged and retains the gripper command; Reset rejects observations from the previous scene epoch.

06

Retain the reserved failure

Correct sensing behavior without relaxing deadlines.

The first frozen 15-case protocol passed 14/15 checks and completed 9/10 placements. A noisy-blue inventory phase expired its active motion lease while stationary. Explicit supervised Hold was added for stationary sensing, retaining heartbeat and freshness requirements. Three new development scenes completed, and the next motion command still reactivates the same deadline. The original failed protocol is preserved.

What this demonstrates

A legitimate simulation prototype.

A controlled parts-staging scenario integrates robotics, practical vision, multimodal task selection, a learned robot model, reusable ROS interfaces and measured failure behavior.

Where the evidence stops

Three known opaque cuboids, fixed trays, calibrated simulated cameras and idealized sensors. Task phases remain engineered. The dependable model learns kinematics; it is not a VLA, reinforcement-learning controller or end-to-end visual action policy.

Software rendering is slower than real time. Pausing simulated physics is not a physical emergency stop. Hardware calibration, protective functions, cluttered arbitrary objects and long-duration deployment require separate validation.

Contribution and foundation

Workcell, perception, supervision, learning pipeline, interfaces and evaluation are project additions developed with AI-assisted coding. Google DeepMind Menagerie supplies the licensed Panda assets; Qwen supplies pretrained model weights. MuJoCo, ROS 2, PyTorch and llama.cpp provide the software foundations.
